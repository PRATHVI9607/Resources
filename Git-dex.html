Unit 0: Foundations and Setup

What Git and GitHub are, why they change how you code, and getting Git, the GitHub CLI and a login working on Windows, macOS or Linux.

IN THIS ENTRYGet the mental model that every later command fits into. No typing yet.
Git
A program on your computer that records snapshots of a project folder. Every snapshot (a commit) remembers the full state of every file, who made it, when and why. You can compare, undo, branch off and merge snapshots, all offline.
GitHub
A website that hosts Git repositories and adds teamwork on top: pull requests, code review, issues, Actions (CI/CD), releases, security scanning. Git works without GitHub; GitHub is built on Git. GitLab, Bitbucket and Azure Repos do the same job.

The four places your code lives

Working treeThe normal files and folders in your project. Your editor only ever sees these.
Staging areaA draft of the next commit. You choose which changes go in, so one commit can be "fix login bug" even if you also touched other files.
Local repositoryThe hidden .git folder. It holds every commit ever made, so history, diffs and branches work offline.
RemoteA copy of the repository somewhere else, usually GitHub. Named origin by convention.

Editor and line endings (differs per OS)

Git opens an editor for commit messages without -m, interactive rebase and merge messages. Line endings matter because Windows ends lines with CRLF and macOS/Linux with LF; without a rule, every line shows as changed when teammates on different systems touch a file.


git config --global core.editor "code --wait"
git config --global core.autocrlf true

core.autocrlf true: convert LF to CRLF when files are checked out, back to LF when committed. The repository always stores LF. Prefer Notepad? git config --global core.editor notepad.


git config --global core.editor "code --wait"
git config --global core.autocrlf input

core.autocrlf input: if a CRLF file sneaks in (pasted from Windows), convert it to LF on commit; never convert on checkout. Prefer a terminal editor? git config --global core.editor nano.

The object database
Git stores four kinds of object in .git/objects, each named by the SHA-1 hash of its content: a blob (one file's content), a tree (a folder listing: names pointing to blobs and other trees), a commit (a tree plus parent commit(s), author, date, message) and an annotated tag. Same content gives the same hash, so identical files are stored once.

Notice dex.js did not change between the two commits, so both trees point to the same blob. A commit is a full snapshot, but unchanged files cost nothing.

What this explains

  • A branch is a movable label on a commit. Creating one is instant and free.
  • HEAD is "where you are": normally it points to a branch; when it points straight at a commit you are in detached HEAD (Unit 3).
  • Commits are never edited. Amend, rebase and cherry-pick create new commits with new hashes and move the label. The old commits still exist for a while, which is why reflog can rescue you.
  • History is tamper-evident. A commit's hash covers its tree and its parent's hash, so changing anything old changes every hash after it.
  • Every clone is a full backup with the complete history.

GitHub Actions
GitHub's built-in automation. A workflow (a YAML file in .github/workflows/) is triggered by events (push, pull_request, a schedule, a tag...). It contains jobs that run on fresh virtual machines called runners; each job is a list of steps, either shell commands (run) or reusable actions (uses). Free for public repos; private repos get a monthly allowance of minutes.

Commit names cheat sheet

HEAD current commit, HEAD~2 two back on the first-parent line, HEAD^2 second parent of a merge, main tip of a branch, origin/main your bookmark of GitHub's main, v1.0.0 a tag, "HEAD@{3}" where HEAD was 3 moves ago, ORIG_HEAD before the last merge/reset/rebase, main..feature commits on feature not on main, HEAD:path a file in a commit.

IMPWhat are the three local areas a change moves through, and which command moves it between each?

Working tree, staging area (index), repository. git add moves changes from the working tree to the index; git commit records the index as a commit. git restore --staged and git restore move them back.

IMPWhat is a branch, physically?

A file in .git/refs/heads/ containing one commit hash. Committing moves it to the new commit. HEAD normally points at the current branch.

IMPWhen does a merge fast-forward, and when does it create a merge commit?

Fast-forward when the current branch has no commits since the other branch split off: the label just moves. If both sides have new commits, Git does a three-way merge from the merge base and records a commit with two parents.

IMPreset or revert for a commit that is already on GitHub's main? Why?

revert. It adds a new commit and does not rewrite history. reset would remove commits teammates already have and require a force push.

IMPWhat is the difference between git fetch and git pull?

fetch only downloads and updates origin/* bookmarks. pull is fetch plus merge (or rebase with --rebase) into your current branch.

IMPYour push is rejected with "fetch first". What happened and what do you run?

Someone else pushed commits you do not have, so your push is not a fast-forward. Run git pull --rebase (resolve any conflicts), then git push.

You ran git reset --hard HEAD~3 by mistake. How do you get the commits back?

git reflog shows the previous position as HEAD@{1}; run git reset --hard "HEAD@{1}". Uncommitted edits lost by the reset cannot be recovered.

IMPWhat is the golden rule of rebasing?

Do not rebase commits that others have based work on (shared branches like main). Rebasing your own feature branch is fine; push it with --force-with-lease.

Why --force-with-lease rather than --force?

It only overwrites the remote branch if it still matches your origin/branch bookmark. If a teammate pushed meanwhile, it refuses instead of deleting their commits.

You added node_modules to .gitignore but it still shows as modified. Why?

It was committed before the rule existed, and .gitignore only affects untracked files. Run git rm -r --cached node_modules and commit.

What do the conflict markers <<<<<<<, ======= and >>>>>>> separate?

From <<<<<<< HEAD to ======= is your current branch's version; from ======= to >>>>>>> other is the incoming version. With zdiff3 a ||||||| section shows the original. Remove all markers, keep the right code, git add.

Squash and merge vs rebase and merge on GitHub?

Squash puts the whole PR on main as one new commit. Rebase replays each PR commit onto main without a merge commit. Both keep main linear; squash hides the PR's individual commits.

IMPWhy does the CI workflow use a matrix of three operating systems?

To catch platform bugs (paths, line endings, shell differences, case-sensitive file names) before they reach users. Each OS and Node combination runs as its own job.

How does git bisect run decide whether a commit is good or bad?

By the command's exit code: 0 good, 1 to 127 bad (except 125, which means skip this commit).

Why quote "HEAD@{1}" in commands?

PowerShell treats { } as a script block and would mangle it. Quotes are harmless in other shells, so quoting always works everywhere.

You leaked an API key in a public repo. First action?

Revoke or rotate the key. Rewriting history comes after, and is optional once the key is dead.
